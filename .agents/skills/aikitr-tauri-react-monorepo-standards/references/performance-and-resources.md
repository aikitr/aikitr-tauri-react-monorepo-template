# 04 性能预算与资源生命周期

适用：生产交互与资源消耗；索引、流式 IO、大表格和 sidecar 在实际启用时细化。功能负责人拥有性能场景和数据集，平台负责人测量原生进程/WebView，发布负责人比较发行基线。

## PERF-BUDGET · 测量与预算契约

**必须**为承诺的关键场景记录：场景名、目标设备/OS/架构/WebView、应用 build、数据规模、冷/热状态、开始/结束定义、样本数、统计量、预算、噪声范围、负责人。预算由实际基线和体验需求确定；文档中只写“足够快”或引用一组全项目通用毫秒数均不足以形成门禁。

| 指标           | 测量语义与范围                                                                  |
| -------------- | ------------------------------------------------------------------------------- |
| 冷启动/恢复    | 进程启动→可交互；初始化失败/降级单独计数，不用只显示空壳冒充完成                |
| 搜索/导航/编辑 | 输入或动作→可见结果；区分 debounce、传输、Rust 执行和 React 渲染                |
| IPC/任务       | 载荷字节数、调用频率、排队时间、执行时间、取消收敛时间                          |
| 内存           | Rust、WebView、sidecar 各自以及整体；统一 OS 工具口径，重复窗口操作后的稳定趋势 |
| CPU/IO/能源    | 前台操作、后台索引、空闲与托盘隐藏场景；按目标设备工具测量                      |
| 包与缓存       | 安装包、前端资源、依赖增量、索引/日志/缓存容量；区分压缩与展开大小              |

**必须**用发行配置和真实目标 WebView 验证桌面预算；开发 Chrome 的平均值只能用于定位。样本足够时报告 P50/P95 等分位数与异常样本，不仅平均值；记录采样方法并避免用极少样本推断稳定尾延迟。React Profiler 有自身开销和生产构建启用条件，适合定位组件问题，不能代替进程总体验测量。

## PERF-EXECUTION · 前端、IPC 与原生的默认策略

- **默认**按路由/重型功能按需加载，避免 UI 根 barrel 无意引入大型业务库；优化依据实际 bundle 分析和热路径，不为风格给每个组件 memo。
- **数据规模需要时**列表分页/增量加载或虚拟化；稳定 key、可访问焦点与选择一致。搜索过滤不反复在主线程扫描巨大数据集；CPU 密集前端工作评估 worker 或原生实现。
- **默认**IPC 使用业务粒度、分页/游标与有界载荷；合并高频状态通知，流式任务按需用 channel。只用 debounce 不能解决发送端持续堆积，必要时定义背压、丢弃可替代进度和消费者断开行为。
- **必须**为长期运行任务定义并发上限、队列容量、任务截止/取消、失败退避和检查点。数值由设备和业务确定；避免每个搜索启动一个无上限线程或子进程。
- **必须**区分取消视图等待与取消底层工作；长任务支持实际协作取消时测量收敛，无法取消时限制规模并丢弃过期结果。阻塞 IO/CPU 不因 async 标记自动变得非阻塞。

## PERF-RESOURCES · 资源所有权

| 资源                             | 所有者与结束点                                        |
| -------------------------------- | ----------------------------------------------------- |
| 事件监听、定时器、观察者、订阅   | 注册模块；组件/功能卸载或作用域结束，处理异步注册竞态 |
| fetch/流、object URL、worker     | 发起者；完成、替换查询、关闭页面或退出身份            |
| DB 连接、文件句柄、Rust channel  | 原生服务/任务；事务/任务结束或统一退出流程            |
| 子进程、系统快捷键、watcher      | 平台服务；明确进程/窗口/身份作用域并验证释放          |
| 查询缓存、索引、日志、持久化任务 | 各自能力所有者；容量/期限/失效和清理可观测            |

**必须**防止内存或磁盘队列无界增长；后台任务在窗口隐藏、设备睡眠/唤醒、网络恢复后按策略继续或暂停。跨睡眠超时与凭据过期使用正确时钟/重新检查，不从 UI 还活着推断原生任务仍健康。

## PERF-ACCEPT · 门禁与证据

依赖/渲染/IPC/任务改动影响关键路径时，运行相关基准并比较同设备同数据集的基线；噪声大的测量复测后判断，不把一次 CI 数值直接当缺陷。记录超预算的变化、原因、影响和有期限的例外，不能通过重置基线抹去回归。

验收包含发行构建基线、重复打开/关闭窗口后的资源趋势、空闲/后台场景、最大承诺数据规模、任务取消与队列边界。自动 CI 无法可靠测量的平台可用固定设备验收流程，证据随发布关联。方法依据见 [资料来源](sources.md)，退出与清理见 [生命周期规范](desktop-lifecycle.md)。

测试数据/并发隔离见 [测试策略](testing-strategy.md)，支持设备与 WebView 组合见 [平台兼容](platform-compatibility-and-distribution.md)。
