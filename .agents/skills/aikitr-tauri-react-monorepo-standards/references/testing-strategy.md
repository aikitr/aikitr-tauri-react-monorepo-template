# 12 测试策略与测试资产治理

适用：现有能力的正确性与发行证据。feature/domain 负责人拥有业务用例，UI 负责人拥有组件契约，原生/服务负责人拥有真实适配器与协议；发布负责人汇总目标环境证据。单维护者可兼任；不为模板安装所有测试框架。

## TEST-LAYERS · 分层与风险映射

| 层级          | 证明对象                                 | 主要边界                                  |
| ------------- | ---------------------------------------- | ----------------------------------------- |
| 纯业务单元    | 规则、状态转移、计算、错误/冲突语义      | Rust/TS 实际规则；少依赖环境              |
| 组件/功能行为 | 用户输入、反馈、键盘/焦点与平台能力调用  | 可替换网络/IPC；不证明真实权限或磁盘      |
| 适配器集成    | 文件、数据库事务、HTTP、实际序列化与取消 | 临时真实存储/受控服务；错误与副作用       |
| 契约与消费者  | 生产者输出、消费者解析、兼容与公开 API   | 实际 producer/consumer；不是两端共享 mock |
| 桌面/端到端   | 关键完整流程、原生窗口、权限、安装与升级 | 承诺环境中的候选产物或受控测试构建        |

- **必须**按变更指出可能破坏的行为及对应验证；断言可观察结果/副作用与拒绝条件，不仅调用次数、DOM 大快照或实现私有字段。
- **默认**把多数业务规则放到快速单元/集成层，少量端到端覆盖关键跨层流程；比例、覆盖率与预算来自风险和测量。低影响可逆改动按现有门禁验证，不新增镜像实现的测试。
- **必须**区分 mock、测试构建和真实发行产物证明的范围。Native API mock 通过不代表 Rust 权限、OS 对话框、磁盘或真实 IPC 已验证；覆盖率不能代替失败、竞态和恢复场景。

## TEST-CONTRACT · 协议与兼容测试

- **必须**对变化的 HTTP/IPC/持久化契约验证真实序列化、运行时解析和消费者行为，包括缺失/未知字段、null、边界数值、错误与版本不匹配。类型生成、快照或两端引用同一 schema 都不能单独证明跨语言 wire 兼容。
- **默认**由协议所有者维护有来源/版本的有效、无效和历史样例；生产者实际生成结果供消费者验证。涉及独立发行旧客户端时按支持窗口测试真实旧消费者，不宣称“最新版两端通过即向后兼容”。
- **按需**使用 consumer-driven contract、性质测试、fuzz 或模型测试处理多消费者、复杂解析/路径与高风险状态机；不要求所有 UI 文案采用这些工具。

## TEST-ISOLATION · Fixtures、并发与确定性

- **必须**隔离会变化的测试状态：临时目录/数据库、账户/租户、队列、缓存、mock 和进程。并行运行有独立命名空间与所有者；清理只删除本次创建对象，不碰真实用户目录或共享生产服务。
- **默认**通过 fixture/context factory 显式建立依赖和释放资源；共享 setup 只保留确实通用的初始化，避免全局业务账号。数据使用合成样例；真实样本须经过批准的脱敏与访问流程。
- **必须**测试不依赖执行顺序或其他用例残留。对时间、随机种子、网络、locale 和环境差异有控制或明确记录；必要真实时间/OS 行为通过带期限的状态条件等待，不靠无界等待或随意长 sleep。
- **默认**随机/并发问题保留可复现 seed、操作序列和受控故障；覆盖提交后崩溃、响应丢失、磁盘满、权限拒绝及身份切换等实际风险。人工故障注入限定测试资源。

## TEST-EXECUTION · 执行、重试与失败证据

- **必须**记录当前提交、工具链/OS/WebView、测试选择与发现/执行/跳过数量、首轮结果、每次重试及失败附件。环境故障与产品失败分类；重跑成功不能删除首轮失败或把不稳定用例描述为稳定通过。
- **默认**重试只按记录的有限策略，flaky 隔离沿用有负责人/期限/替代验证的例外。失败时收集最小必要日志、截图、trace 或 dump，限制敏感信息和保留期。
- **必须**检查缓存的实际输入包含测试源码、根配置/setup、fixtures、共享源码与影响结果的配置；结果可追溯到同一输入。只修改标题不能证明测试执行或重算。
- **桌面自动化按实际驱动选择**；核对当前官方平台与驱动模式支持，不永久认定某 OS 无法自动化。嵌入 WebDriver/后端执行插件提供的测试能力与发行权限面分离；驱动不足时记录人工或替代证据和范围。

## TEST-ACCEPT · 验收与退出条件

测试方案至少指出风险→层级→真实或替身边界→环境/所有者→预期结果→证据。关键行为用例应能捕获相应缺陷；对迁移、权限、幂等、缓存输入等脆弱控制，可用已知违规样例或受控缺陷验证断言有效。

必需检查失败、未执行或无法证明的范围保持可见，按风险修复或评审精确例外；不以覆盖率达到统一数字结束验证。检查已覆盖实际风险后停止无关扩测。发行平台证据见 [兼容与分发](platform-compatibility-and-distribution.md)，原有门禁与缓存见 [工程规范](tooling-and-delivery.md)，工具依据见 [资料来源](sources.md)。
