# 05 设计系统与组件变更治理

适用：共享 ui、主题 token 和实际消费者。ui 维护者负责视觉原语/API，业务负责人负责业务组合，应用负责主题/locale/provider 的装配。团队小可由同一维护者承担，不要求单独设设计系统团队。

## UI-OWNERSHIP · Token、组件与业务归属

| 层级       | 默认约定                                                          | 边界                                             |
| ---------- | ----------------------------------------------------------------- | ------------------------------------------------ |
| 基础 token | 色阶、字号、间距、圆角、阴影，按当前 Tailwind/shadcn CSS 机制表达 | 有单一来源；映射工具命名不随意重命名             |
| 语义 token | background、foreground、muted、destructive 等                     | 组件使用语义；暗色/品牌主题保持语义一致          |
| 原语       | Button、Input、Dialog 等                                          | 维持上游名称和合理 Props，允许消费者组合         |
| 通用组合   | 可复用的表单字段、无业务 Table 工具                               | 不内置鉴权、业务请求或应用配置                   |
| 业务组合   | 文件搜索、重命名弹窗、账户选择                                    | 所属 feature/domain，不能因多个页面用到就进入 ui |

- **必须**记录 token 所有者和修改影响；应用可在主题边界覆写约定变量，功能不得悄悄重定义全局 token。存在多品牌时明确共用基础和品牌覆盖，不复制整套组件。
- **默认**避免无语义的自定义色值和一组组件内平行样式变量；确有业务视觉例外留在业务样式并说明适用场景。图标库、字体许可、间距密度、焦点与减少动画策略保持一致。
- **默认**组件支持最少且明确的 variant/size、className、必要的原生 Props、ref 和受控/非受控模式；不为方便包装而丢弃 aria、事件或底座状态属性。

## UI-CONTRACT · 公共 API 与变更分类

**必须**把 Props、导出路径、默认行为、DOM/ARIA 语义、ref、组合方式、CSS token 和数据属性中已被消费的部分视为契约。删除导出、改变默认值/按钮提交语义、从 Radix 改 Base UI、改变受控模式均需影响分析，不能只作为“视觉更新”。

- **默认**兼容变化直接更新，破坏性变化提供消费者迁移清单与必要的期限明确兼容层；不要永久保留成对的旧/新别名。
- **内部包**可以统一 PR 原子迁移所有消费者；**独立发布包**使用语义版本和变更记录。私有/内部包不代表可以跳过消费者验证。
- **生成源码**由团队维护，记录来源、所用底座/style、CLI 版本和必要的本地差异。升级 npm 底座与更新 shadcn 源码分开验证；CLI 最新不代表组件源码最新。

## UI-UPSTREAM · shadcn 更新流程

1. 在当前组件配置下核对官方变更和工具支持，固定本次使用的 CLI/源版本或记录可追踪结果；在临时位置或 CLI 预览模式查看差异。
2. 区分上游修复、API/DOM 变化、设计 token 变化、本地定制与依赖变化；逐项决定合并和兼容，不直接覆盖整个 ui。
3. 核对直接 `cn` 依赖、组件底座 API、ref/event 合并、样式扫描、包 exports 与 CSS 副作用。
4. 更新组件与消费者，并运行受影响组合场景。恢复/回退方式必须考虑与消费者的版本匹配。

此流程支持源码审查，不要求每次新增普通组件都新建一套注册表或发布平台。具体 CLI 参数以当前官方文档为准。

## UI-ACCEPT · 文档与验收矩阵

使用实际项目文档或 Storybook 等现有载体展示公共 Props、组合示例、状态、限制与迁移说明；有真实消费者需求再引入文档工具。

| 变更场景                       | 必须验证                                                            |
| ------------------------------ | ------------------------------------------------------------------- |
| 按钮、表单、导航、trigger 组合 | 点击/键盘、submit 类型、真实链接语义、ref、事件组合，无嵌套交互元素 |
| Dialog/Menu/Popover            | 打开关闭、焦点/返回焦点、Esc、禁用与受控状态、portal 层级           |
| token/布局/字体                | 明暗主题、系统缩放、长文本、对比度、最小窗口与实际 WebView          |
| 公共 API/exports/底座          | 所有实际消费者 typecheck/build，业务交互回归，兼容层与迁移记录      |
| 国际化/RTL/减少动画            | 标签与可访问名称、逻辑方向、焦点顺序、用户偏好                      |

截图证明视觉，交互测试证明行为，消费者构建证明接口；三者按变更范围选择，不能互相替代。依据见 [组件规范](naming-and-components.md) 与 [资料来源](sources.md)。

公共组件变更的完整可访问性范围见 [无障碍与交互](accessibility-and-interaction.md)，跨消费者协议和测试隔离见 [测试策略](testing-strategy.md)。
