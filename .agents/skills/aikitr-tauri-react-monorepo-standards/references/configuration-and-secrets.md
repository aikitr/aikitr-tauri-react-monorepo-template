# 13 配置、环境与密钥治理

适用：构建、运行、部署配置与实际使用的秘密；远程配置/feature flag 仅在启用时生效。应用启动层装配公开配置，feature 消费类型化接口；平台/服务负责人控制秘密获取，发布负责人关联版本与环境。共享 packages 不直接读取某个应用的环境变量。

## CONFIG-SOURCES · 分类、来源与优先级

| 类别         | 语义                        | 必须明确                                   |
| ------------ | --------------------------- | ------------------------------------------ |
| 构建公开配置 | 随 bundle/原生产物固定      | schema、mode、缓存输入、产物与环境标识     |
| 运行公开配置 | 安装后由实际加载协议读取    | 来源、版本、优先级、授权范围、重载与恢复   |
| 用户偏好     | 用户可调的业务展示/本地选项 | 默认值、持久化、账户/设备范围、迁移        |
| 组织托管策略 | 管理者限定设备/账户行为     | 策略来源、验证、覆盖与撤销，和用户选项关系 |
| 秘密/凭据    | 服务、用户或发行授权        | 可信所有者、访问/轮换/撤销、日志与导出排除 |

- **必须**为实际配置记录来源与明确优先级，不让同名字段在多个文件中隐式争胜。schema 校验类型、范围和关键 URL/身份环境；配置无效时给安全错误与恢复，不能悄悄切到生产账号或不安全默认。
- **默认**按类别分层后由应用注入类型化快照/接口；现有可靠配置工具可保留，不强制所有项目采用同一环境库。配置版本独立记录，不把字段数量或应用版本当作配置 schema。
- **必须**区分 Vite mode、构建时环境与安装后的运行时配置。import.meta.env 的构建替换不会因改用户机器 .env 自动更新；若需要动态 endpoint，实际实现并验证运行时加载/重载机制。

## CONFIG-ENVIRONMENT · 环境隔离与变更

- **必须**明确开发、测试、预发布、生产中实际使用的服务/账号/存储/发行渠道。预发布不默认访问生产写接口，测试使用隔离身份；身份 issuer、audience、回调与 endpoint 切换保持一致。
- **必须**让影响产物结果的公开构建配置参与缓存，并关联构建记录；签名秘密只在受控发行步骤使用，不作为普通缓存内容。产物上公开环境/服务标识采用安全字段，不展示 token。
- **启用动态配置时必须**校验来源与允许字段，记录 revision、获取时间、适用应用/schema/环境、加载失败与过期策略；不能远程下发任意 JS、shell、CSP 放宽或新的原生权限。必要来源完整性依据实际威胁模型验证，配置文件存在不等于可信。
- **默认**动态更新以完整校验后的快照原子生效；受影响连接、Query、账户数据和队列按协议排空、重建或拒绝变更。变更 identity/endpoint 时不能沿用旧环境 token/cache 发送到新来源。记录发布与恢复的非敏感配置 revision/摘要，秘密不直接生成公开可猜测摘要。

## CONFIG-SECRETS · 获取、轮换与泄漏

- **必须**将任何进入客户端 bundle、静态资源或固定原生二进制的值视为可提取；VITE_*、自定义 envPrefix、define 和构建脚本都可能暴露。公开客户端 ID 可公开；供应商服务私钥/机密凭据留在可信服务端或受控发行环境。桌面 public client 不通过编译到 Rust 获得服务端秘密保密性。
- **默认**提交不含秘密的配置字段说明/示例，真实本地文件按需要忽略；仓库忽略和字符串混淆不能撤回已提交/发布的秘密。秘密访问按用途与环境最小授权，开发不借用生产签名密钥。
- **必须**记录秘密 ID/用途、持有方、创建/轮换/撤销负责人、消费版本与恢复策略；记录元信息而非值。轮换涉及旧密文读取或签名信任时先确认兼容/重加密，再按策略退役旧密钥；不能销毁唯一解密钥匙后宣称可恢复。
- **发生泄漏时必须**按实际授权止损、撤销/轮换，检查历史 commit、产物、日志与副本影响，并验证旧凭据失效；删当前文件不足以证明修复。受控 vault/托管秘密服务按需要采用，不预装云平台。

## CONFIG-FLAGS · 功能开关生命周期（启用时）

- **必须**为每个 flag 定义稳定 key、类型、所有者、用途、目标范围、默认/异常值、评估位置、兼容条件、失效期限或复查事件与删除计划。临时发布/实验开关默认有退出期限；长期运维控制记录理由与复查机制。
- **必须**由业务风险决定缺失、过期、远端不可用和未知值的安全行为。风险能力默认关闭/拒绝；不把所有体验 flag 一律判 false，也不把 unknown 一律放行。flag 控制体验/发布策略，真实资源授权仍在可信边界。
- **默认**一次任务使用一致的策略快照；涉及身份的评估上下文隔离，必要关闭策略说明对在途任务与恢复的影响。flag 不能取消已执行远端副作用，回退须满足数据/协议兼容。
- **必须**测试开/关/缺失/异常值、离线或过期、旧客户端与变更中任务；退役删除分支、配置和无用测试并检查实际消费者，不永久保留没人维护的组合。

## CONFIG-ACCEPT · 验收证据

提供来源/优先级/schema 表、环境与安全公开指纹、发行产物秘密检查、错误配置拒绝与切换验证；实际使用秘密时附不含值的轮换/撤销证据。远程配置/flag 另提供故障默认值、身份隔离、期限和退役记录。未启用动态能力注明不适用。

Vite 与秘密管理依据见 [资料来源](sources.md)，会话隔离见 [认证规范](identity-and-sessions.md)，构建输入见 [工程规范](tooling-and-delivery.md)。

实际配置修订与发布记录通过 [落地模板](standards-adoption-and-maintenance.md) 关联，不把配置审批或 flag 变更推定为已获外部执行授权。
